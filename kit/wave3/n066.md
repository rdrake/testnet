The fork stamps a message's client-facing `@time` from an armed event time (`client_event_ms`), so live delivery and stored history agree. Several paths stamped the wrong time.

- **A send that armed only a msgid took the time an earlier event had armed.** `sendcmdto_set_s2s_tags()` arms that time too, and neither the end of the line nor a later `sendcmdto_set_client_msgid(msgid)` cleared it. On a test server, an invite-notify carried the time of a line from nine seconds earlier.
  - `sendcmdto_set_client_msgid()` no longer arms a time. Those lines take the clock, or a `sendcmdto_set_client_time()` override.
  - An event that has a time arms both through `sendcmdto_set_client_event()`.
  - The end of the line clears an S2S-armed time when no client msgid holds it.
  - Every caller that armed a bare msgid now arms its whole event:
    - ACCOUNT (three paths) and AWAY (both) with the time they relay;
    - INVITE, the burst JOIN and the host change with the msgid's mint time.
- **SETNAME used `gettimeofday()`.** It now takes `history_event_time_ms()`, the history clock every other event uses: the link's time when the msgid came with the line. ACCOUNT's relay time comes from the same place.
- **The plain-text lines of a multiline batch had no batch time.** These are the lines sent to a client without draft/multiline (`send_multiline_fallback()`). They now carry the batch's time, including the truncation notice.
  - The function takes the time as a parameter and restores the caller's override afterwards.
  - The client-tag composers (`format_message_tags_with_client*`) now honour the batch time as well. Before, a fallback line with client-only tags was stamped with the wall clock.

**Testing:** build and all CMocka suites pass. New CMocka cases in `send_s2s_tags_cmocka`:
- a bare msgid after an S2S-armed time, with and without the end of a line in between;
- an armed event surviving the end of the line;
- the batch time winning on every client-tag composer.

I also checked on two linked servers: an invite-notify sent a few seconds after a relayed PM now carries its own time. Before, it carried the PM's.
