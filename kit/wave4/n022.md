`m_setname()` and `ms_setname()` treated the new realname as unchanged when `ircd_strcmp()`, which ignores case, said it equalled the old one. `SETNAME :John Smith` after `john smith` did nothing: no echo to the sender (the setname spec expects one on success), no relay, no update.

**The fix:** both compare with `strcmp()`, so only an identical realname is a no-op.

**Testing:** build and all CMocka suites pass. On two linked servers, a case-only SETNAME now echoes to the sender, and WHOIS on the other server shows the new case.
