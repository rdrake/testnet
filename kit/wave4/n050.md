Three small bugs inherited from ircu, each a line or two:
- `irc_in_addr_valid()` tested `in6_16[0]` with `x && ~x`. `~` on the promoted unsigned short is an int (`~0xFFFF` is `0xFFFF0000`), never 0, so an all-ones address counted as valid. It now compares with `0xFFFF`.
- `verify_sslclifp()` tested `!cli_sslclifp(cptr)`, the address of an array, which is never NULL. The "no certificate" return was dead code, and a client without a fingerprint failed only because the compare did not match. It now tests the first character.
- `ms_nick()`'s collision path read `cli_lastnick(acptr)` after `exit_client_msg()` had freed `acptr`. It worked only because the freed Client sits untouched on the freelist. It is now read before the exit.

**Testing:** `ircd_in_addr_t` now checks all-0s, all-1s and two near misses; the all-1s case failed before the change. Build and the other tests pass.

The same change is opened against master separately.
