# #242 chathistory: SEARCH and timestamp parsing fixes

Head when copied: 065d4f17

## MrLenin, 2026-11-18T19:08:09Z

Re-reviewed at 065d4f17 (previous review at acefc7e1). Built (debug, no warnings), the CMocka suites pass (96 programs), and each timestamp spelling was run on the tip and on this head, on one server and with a tip requester linked to this PR's responder.

Fixed since the last review: the mixed-build wrong pages (run: `+00:00`, `z`, a one-digit hour and 31 November from a tip requester now give a partial page without `draft/chathistory-end`); unit tests on the real converters; the SEARCH example in the description.

Q1 is implemented as decided (run): the spec form and a leap second are accepted by CHATHISTORY, TARGETS, MARKREAD and SEARCH `before=`; a missing `Z` or fraction, 1 or 6 fraction digits, an offset, lowercase `z`, `Zjunk`, a one-digit field, 31 November and pre-1970 get `FAIL ... INVALID_PARAMS` on all four. Seance sends the spec form.

1. **One departure from Q1: with `CHATHISTORY_STRICT_TIMESTAMPS` at its default FALSE, CHATHISTORY and TARGETS still accept a client's unix `sec[.mmm]`.** Run: `timestamp=1795026936.417` answers a page; `parse_reference()` (`ircd/m_chathistory.c:465`) sends a value without `-` to `history_ref_to_unix()`. MARKREAD and SEARCH refuse it. This is the existing permissive switch, not new code, but Q1 refuses everything else. Either default the feature to TRUE or drop the unix client path, or say in the description that Q1 covers the ISO form and the unix form stays behind that switch.

2. **Textual conflict with #240** in `ms_chathistory()`: #240 renames `parse_s2s_reference()`, which your new unplaced-TIMESTAMP check calls, to `chathistory_parse_s2s_ref()`. The second to land rebases, and the check must keep working on the renamed parser. Semantically they agree.

With #252: keep #252's exact line check and drop this PR's `SEARCH_FED_FIXED` one (`ircd/m_chathistory.c:9827`); with both, an `in=` query is refused up to about 57 bytes earlier than without `in=`.

Could be simpler (optional; the maintainers have asked to stop over-engineering where it isn't necessary): the lenient reading of a server's ISO time (`history_ref_to_unix()` calling `iso_to_unix(..., 0)`, `ircd/history_record.c:770`; about 20 lines plus comments and test table) serves only the upgrade window in which an older fork origin passes a client's text on. Without it those spellings get `E <reqid> 0 U` (a partial page) during the window, as `+00:00` does now; once all fork servers run this, no origin sends them.
