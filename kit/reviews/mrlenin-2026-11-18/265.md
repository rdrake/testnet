# #265 chghost: the user hears its own change, under the old user@host

Head when copied: bc18b812

## MrLenin, 2026-11-18T19:08:03Z

Re-reviewed at bc18b812 (previous review at 79daa0c7). Built, all 96 CMocka suites pass (the new `send_tags_cmocka` case included), and host changes were run on one scratch server with simulated services: two bouncer sessions, each with a device with chghost and one without, plus two observers, all in one channel, once present and once with every session member away. Not run this round: two servers (a remote device), `-x` and SETHOST (the same code by reading), ASan.

Fixed since the last review: a device without chghost no longer gets a QUIT, JOIN or MODE of its own nick (run); the description's SASL +x timing.

What each recipient now sees on a host change (run):

| Recipient | with chghost | without chghost |
|---|---|---|
| The user's own connection | `:nick!u@oldhost CHGHOST u newhost`, then 396 | 396 only (plus an `AWAY` of itself when away, as before this PR) |
| The user's other devices | the same CHGHOST, when they share a channel | nothing, except the line in 1 |
| Other users in a shared channel, another user's devices included | CHGHOST with the old prefix | `QUIT`, `JOIN` under the new host, `AWAY` when away, `MODE` when they have status |

1. Low: a device without chghost but with away-notify gets a lone `:nick!u@newhost AWAY :text` of its own nick when the session is away, with no QUIT or JOIN before it (run, seen on both such devices). `hide_hostmask()` calls `away_notify_channel()` after the JOINs (`ircd/s_user.c:2434`; `unhide_hostmask()` at `:2534`), and `away_notify_channel()` (`ircd/m_away.c:248`) sends with `one = NULL` and `SKIP_CHGHOST` only. A client merely sees its own away restated under a host it was never told about, but the device should see nothing. Fix: those two loops are its only callers, so send there with `one = sptr` and `SKIP_CHGHOST | SKIP_SESSION`; that also drops the user's own redundant copy, which predates this PR.

Mixed builds: CHGHOST is generated per server, so during a split deploy a device on an older fork build still gets the QUIT and JOIN from its own server.
