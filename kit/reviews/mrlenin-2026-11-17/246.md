Reviewed at ee7f51e2. Built, the CMocka suites pass (97 suites), and REHASH, SIGHUP and real GitSync applies were run on a scratch server, also under ASan (no reports); BSD was not run.

The follow-up commits work (run): a valid commit that met a changing ircd.conf is put back and applied at the next sync, and a bad commit costs one extra check, not a second rehash.

1. **Every check blocks the main loop in proportion to the hard descriptor limit.** `run_check()` closes every number up to `_SC_OPEN_MAX` (`ircd/conf_precheck.c:61-65`), which boot raised to the hard limit. Run, REHASH to PONG: 37-50 ms at a hard limit of 1024, 398-477 ms at 524288. With `/bin/true` as the check at 524288: 303-312 ms with the loop, 1.3-1.4 ms with `close_range(3, ~0U, 0)`. Fix: `closefrom(3)` under `HAVE_CLOSEFROM` (`configure.in:119` checks it; `gitsync_child_close_fds()`, `ircd/gitsync.c:164`, uses it), then `close_range()` on Linux, then the loop; or `posix_spawn()`.
2. **A check that times out lets the rehash through after the wait, and retries multiply it.** A timeout is `CONF_PRECHECK_UNAVAILABLE` (`conf_precheck.c:210-216`); `rehash_precheck()` then goes ahead, or returns -1 if the file changed (`s_conf.c:1937-1951`) and `rehash()` checks again (:2042-2056). Run: `-k` child stopped, broken second Port block: 10.0 s blocked, then the old partial rehash closed that listener. On GitSync, a bad commit whose restored-file check also times out falls back to a full rehash (`gitsync.c:1651-1655`) that times out again: 20.5 s (run). Fix: abandon on a timeout, never retry after one, and let `conf_file_check()` tell "did not finish" from "did not run" so GitSync neither rehashes nor refuses on a timeout.
3. **A valid commit is refused when ircd.conf is caught mid-write.** `rehash_precheck()` compares the file only after a check that passed or did not run (:1936, :1951); one that reports errors abandons at once. GitSync restores, the restored-file check passes, and the commit is refused "until the content changes". Run: a line appended to ircd.conf during the first check, removed when it exits: "Config parse error in file ircd.conf on line 24", then the refusal. Fix:
   ```diff
      }
    
   +  if (!rehash_conf_unchanged())
   +    return -1;
      conf_error = 1;       /* conf_get_error_flag(): GitSync restores its copy */
   ```
   An include replaced non-atomically gives the same refusal (traced).
4. **The `-k` child writes into the live log files and syslog**, the latter under the ident "exe" (`argv[0]` is `/proc/self/exe`). Every abandoned rehash adds `SYSTEM [CRIT]: Failed to read configuration file ircd.conf` to the live log, tripping CRIT alerting for a rehash that changed nothing; a realistic fork config adds about 11 lines per check ("sent CAP NEW to cap-notify clients"). Run, with an `LD_PRELOAD` trace. Fix: under `BOOT_CHKCONF`, turn file and syslog output off before `log_init()`, and exec with `argv[0]` set to the real path.
5. **No reason when `pipe()` or `fork()` fails** (`conf_precheck.c:134-135`, `:144-147`). Run with `RLIMIT_NPROC=1`: fail open, no errno. Add `strerror()` via `note_end()`, and name the resolved binary, not `/proc/self/exe`.
6. By reading: `kill(-pid, SIGKILL)` at :208 runs after the leader was reaped, when the pgid can be reused; the `waitpid()` after a timeout kill (:212) is unbounded, so a check in uninterruptible sleep blocks the server (plausible).
