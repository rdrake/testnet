- **The extras are no longer gated.** ATTACH, DETACH, LIST, PROFILE and REPLAY work on any connection, with or without `evilnet.github.io/persistence` and whatever `PERSISTENCE_DRAFT_EXTRAS` is set to. ibutsu pointed out that the draft says implementations SHOULD ignore unrecognized subcommands (so the command is meant to be extended), and that a gate stops a bouncer user on a client without the cap from adjusting auto-replay. The gate also protected nothing: each extra requires the account (ATTACH and LIST also accept a completed SASL exchange before registration) and acts only on that account's own sessions and settings, and the spec's own SET needs no cap. The vendor cap now only announces the extras (its token value) and names the restore batch type; `PERSISTENCE_DRAFT_EXTRAS` only keeps the old names for clients written against them (the value on `draft/persistence` and the `draft/persistence` restore batch type). A subcommand the server does not have is still answered with `FAIL PERSISTENCE INVALID_PARAMETERS`. New `persistence_cmocka` covers the dispatch.
