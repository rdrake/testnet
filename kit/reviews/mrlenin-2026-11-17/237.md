Reviewed at 568f44dc. Built (debug, with RocksDB and zstd) with no warnings; all CMocka suites pass (96 suites, 2,374 cases), `log_async_cmocka` passes 100/100 plain and 30/30 under ASan, and the thread counts, REHASH toggling and a load run were checked on a scratch server.

The startup move holds: nothing submits work or logs through the writer before the new start point, and `-k` or a copy refused the PID file starts no thread. Fixed by the newest commit: syslog no longer gets the file's timestamp and newline from queued lines or from the full-queue direct write (checked by stress and on a live server).

1. A full queue still writes the caller's line ahead of every older queued line, so order within one thread, the main thread included, is lost under a burst. `log_async_write()`, `ircd/ircd_log_async.c:349-388`. Run: a `log_async_cmocka` case that fills the ring behind a slow writer and adds one line sees that line land before the one in flight and all the fills; 4 producers with a 200 µs write gave 1,220 to 1,324 out-of-order lines in 8,000; under TSan, scheduling noise alone gave 3 in 80,000. No line was torn. The direct write already costs the caller one blocking `write()`, so waiting for the writer to free a slot costs the same and keeps the order:
   ```c
   -  if (buffer_full()) {
   -    ... timedwait 1 ms ... fallback write ... return 1;
   -  }
   +  while (buffer_full()) {
   +    pthread_cond_wait(&log_async.not_full, &log_async.mutex);
   +    if (!log_async.accepting || !RUNNING())
   +      goto again;            /* drain-wait / -1 path */
   +  }
   ```
   With that, `again:` must unlock and return -1 on `!RUNNING()` once queueing is on, `log_async_shutdown()` must signal `not_full` as well as `not_empty`, and `log_async_set_accepting(0)` should broadcast `not_full`. `full_ring_spurious_wakeup_is_not_room` (`ircd/test/log_async_cmocka.c:660`) asserts the return value 1 of the fallback, so it would change too. If you keep the bounded wait, the reordering of a burst over 4,095 lines needs documenting.

2. A REHASH or `/SET` of `THREAD_POOL_SIZE` is silently ignored, and `/GET` shows a value that is not in force. Run: pool 7, REHASH to 3, still 12 threads, nothing logged. `ircd/ircd_features.c:1063` has no notify. Fix: a notify that logs "THREAD_POOL_SIZE %d takes effect at restart (running %d workers)", with a pool accessor for `num_workers`.

3. Nothing tells the operator async logging is on, and a crash (abort, assert, SIGSEGV, kill -9, OOM kill) loses up to 4,095 queued lines plus the one in flight, the ones nearest the crash. By reading. `log_feature_async_logging()` (`ircd/ircd_log.c:401-412`) logs only an init failure. Fix: log "async logging on" and "async logging off (queue drained)" there; optionally put queue depth and fallbacks on a STATS line (`log_async_stats()` has no caller) and the crash cost in readme.features.

4. Optional. One `pthread_create()` failure tears down every worker already created (`ircd/thread_pool.c:221-246`), and every OPER, SETHOST and WEBIRC hash, bcrypt included, then runs on the main loop. Run under `prlimit --nproc` with pool 64. Fix: if `i > 0`, keep `num_workers = i`, warn, and return 0.

5. Optional. `LOG_ASYNC_MAX_ENTRY` (2048, `include/ircd_log_async.h:41`) is smaller than the line `log_vwrite()` builds (`async_buf[LOG_BUFSIZE + 64]`, `ircd/ircd_log.c:561`), so a line over about 2 KB is cut 23 bytes shorter when queued, in the file and in syslog. Fix: size the entry from `LOG_BUFSIZE` plus stamp and newline.

Two invariants hold today but are written nowhere; worth a comment each: `log_async_stop()` destroys the mutex, so it runs only once every other logging thread is gone; and no fork child may log before `exec`.

Description: "release builds never log from workers" holds for pool workers except the out-of-memory path, where `outofmemory()` runs `server_restart()` on the worker.

Operators: an ircd.conf that already sets either key changes behaviour on upgrade without notice: `THREAD_POOL_SIZE` now takes effect, and `ASYNC_LOGGING` adds a thread and a ring of about 8.4 MB. Nothing changes on the wire or on disk, so rollback is clean.
