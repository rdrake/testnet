# #283 description update (re-evaluation of the simplification)

## Delete

```
**Simplified after review:** dropped the tracking of which capabilities each client was told about (`con_capab_told`); CAP DEL goes to all cap-notify clients as before.
```

## Add at the end

```
**Changed after review (re-evaluation):** CAP DEL is targeted again, in a smaller form. The server keeps one set of the capabilities some client was told are offered (listed by CAP LS, ACKed, or sent in CAP NEW) since their last CAP DEL, and sends no CAP DEL for a capability outside it. Switching off a capability that was never on offer (sasl with no SASL server, draft/authtoken with no service) or withdrawing one twice is now silent. This replaces the per-connection record removed earlier: every change of what CAP LS lists goes to all cap-notify clients, so one set for the server gives the same answer, with no field per connection and no per-client DEL list. A client that connected while a capability was off without a DEL having been sent can still get a DEL it ignores.
```
