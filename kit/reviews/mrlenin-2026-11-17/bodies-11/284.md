Three departures from [draft/read-marker](https://ircv3.net/specs/extensions/read-marker):

- With no known timestamp the server sent `MARKREAD <target> timestamp=*`. The spec says the parameter is then "a literal `*`".
- `MARKREAD <target> *` was taken as a get. A client set command "MUST NOT be a literal `*`".
- After a JOIN the server "MUST send a `MARKREAD` command for that channel". Several JOINs got none.

### What changes

- **No marker.** `send_markread()` sends `MARKREAD <target> *`, as the web push line already did.
- **Invalid parameter.** A second parameter that isn't `timestamp=...`, the literal `*` included, gets `FAIL MARKREAD INVALID_PARAMS`. The FAIL echoes the parameter only when it is one word, so `MARKREAD #c :a b` can't split the context or swallow the description.
- **MARKREAD on JOIN.** `send_markread_on_join()` used to send nothing to a client without an account, or when the marker store was down.
  - A client without an account keeps its markers under its session id, so its JOIN now reports those. With no known timestamp it gets `*`.
  - Three JOIN paths never called it, and now do: a channel rename's PART/JOIN fallback, SVSJOIN of a client without an account, and a bouncer alias joining a channel its primary is already in.
  - The line goes out through `send_reply_line()` (new, ircd_reply.c), with the tags `reply_tags()` gives the TOPIC and NAMES around it (`@batch`, `@label`, `@time`), so it sits inside the JOIN's labeled batch, or a session replay's `draft/persistence` batch, instead of beside it.
- **Rename.** Markers are keyed by channel name and are not copied at a rename or relocation: the new name answers `*` until the user next reads there.
- **Shared anchor.** `markread_anchor()` picks the account or session id for both MARKREAD and JOIN.
- **Pure rules.** The parameter rules are in `markread_wire.h`.

### Not in this PR

- Markers set under a session id before the client logs in stay with the session; they are not moved to the account.
- A renamed channel's read point. Markers stay under the old name, so the new name reports `*` until the user next reads.

### Tests

- **CMocka `markread_wire_cmocka`:** the parameter forms and the FAIL context.
- **CMocka `rename_handlers_cmocka`:** the rename fallback's MARKREAD comes before NAMES.
- **CMocka `markread_join_cmocka`** (the real `m_markread.o`): the JOIN's MARKREAD, `*` forms included, goes out as a reply line.
- **The whole CMocka suite passes.**
- **irctest** (Nefarious controller): `testGetNoReadMarker`, `testReadMarkerOnJoin`, `testReadMarkerOnJoinWithStoredTimestamp` and `testWildcardTimestampRejected` now pass. The full runs with and without X3 show no new failures.

**Changed after the second review:** the marker copy at a rename is taken back out (about 60 lines of code and 250 of tests). It cost a store read or two and a write per member on every server at each rename, and it was not relayed, so servers on different builds answered different markers for the same account. `*` for the new name is all the spec asks. Built and all CMocka suites pass.

**Timestamp forms:** alone, this PR still accepts `...30Z` without a fraction, an offset and a two-digit fraction. #242 refuses them; the two merge cleanly.

**With #235:** a textual conflict in `m_markread.c`, both inserting a check after `target = parv[1];`. Keep both, #235's length check first.
