A `PRIVMSG` or `NOTICE` to `@#chan`, `%#chan` or `+#chan` crossed every link as the wall line (`WALLCHOPS`/`WALLHOPS`/`WALLVOICES`, with an `@ ` lead in the text; a PRIVMSG marked with the bare `,P`). This PR lets fork servers pass it as the message it is.

### What changes

- **A server announces `S` in its SERVER flags** (`FLAG_STATUSMSG_AWARE`). Toward an `S` link a status message is `<from> P|O #chan :<text>` with the compact-tag segment `,P<status>`. Every other link gets exactly the line it got before: the wall line, `,P` on a PRIVMSG's toward an IRCv3-aware link, nothing toward a legacy one. One tag region is formatted, so both forms carry one msgid and time.
- **`NOTICE @#chan` and the like go through `relay_channel_statusmsg()` too**, no longer through `m_wallchops` and its siblings: per target of a list, with a msgid, echo and labeled answer like the PRIVMSG, and through the channel's NOTICE checks (`+N`, `+c`). Local members and `S` servers get `NOTICE @#chan :<text>` without the wall lead.
- **A receiver** (`ms_privmsg`/`ms_notice` with `,P<status>`, or a `,P`-marked wall line from an older fork server) delivers it to members with that status or higher and relays it per link the same way. A `,P<status>` line is never delivered as an ordinary channel message.
- **Multiline to a status target is refused** (`401`), as before.

### Not stored

A status message is not stored in history, as on the tip: a message for a channel's ops must not be replayed to everyone who can read the channel's history. The earlier version of this PR stored them; that half is removed (see below).

### Mixed builds

Stock servers, and services behind them, get exactly today's wall line. During an upgrade window nothing is lost or misdelivered; a NOTICE shows an `@ ` lead on older servers and none on servers with this PR. Nothing is written to a store, so a rollback is clean.

### Tests

- **CMocka `send_s2s_tags_cmocka`:** the per-link forms (an `S` link, an IRCv3-aware link without `S`, a legacy link), one tag region for both, and nothing left armed.
- **CMocka `parse_line_cmocka`:** `,P<status>` is read, and any other data is ignored.
- Debug build with no warnings on the current tip (426b2808); all CMocka suites pass.
