When a user's displayed host changed (+x, a login with a hidden host, SETHOST, -x), `hide_hostmask()` and `unhide_hostmask()` sent CHGHOST only to the chghost clients in the user's channels, and only after storing the new user@host. So:
- The user got only 396, never CHGHOST. A client that tracks its own user@host from CHGHOST kept the old one.
- The line's prefix was the new user@host. The chghost spec has `:nick!olduser@oldhost CHGHOST newuser newhost`: the prefix is how the receiver knew the user.

**The fix:** a new `send_chghost()` sends CHGHOST before the new user@host is stored. It goes to the channel members as before, and to the user's own connection if it negotiated chghost (its own caps, not its bouncer session's), as an event line carrying the armed msgid.

**Not covered:** the user's other devices in a bouncer session that share no channel with it still hear nothing; that belongs with the bouncer work. A chghost client registering with SASL and +x now also gets its own CHGHOST, after the end of the MOTD (376 or 422).

**Testing:** build and all CMocka suites pass. On a running server, +x and -x now send the user its own CHGHOST with the old user@host as prefix and a msgid, and channel members get the same prefix.

**Changed after review:** for clients without chghost a host change is a QUIT of the user's nick and a JOIN back, with the MODE that restores its status. The user's own connection was skipped, but a bouncer device of its session shares the nick and the channels, so a device without chghost was told its own nick quit and rejoined. The QUIT now goes through `sendcmdto_common_channels_capab_but_session()`, and the JOIN and MODE skip the user's devices. A device with chghost still gets the CHGHOST, and another user's device is an observer like any other. `send_tags_cmocka` covers it.

**Mixed builds:** CHGHOST is generated per server, so during a split deploy, members on an older server still see the new-host prefix.

**Changed after the second review:** a device without chghost but with away-notify got a lone `AWAY` of its own nick under the new host when the session was away, with no QUIT or JOIN before it. `away_notify_channel()`, which only the two host-change loops call, now skips the user and its session's devices, as the JOIN before it does. That also drops the user's own redundant AWAY copy, which predates this PR. Built and all CMocka suites pass; not re-run on a live server.
